# Актуальные границы проекта

Уточнение пользователя от 5 ноября 2026 года заменяет прежнее решение о сценарии заявки менеджеру. Пользователь отдельно подтвердил сохранение стека **Nuxt + Strapi**.

Основная задача заказчика — получить CMS для управления содержанием сайта и обновлённый дизайн, особенно интерфейс конструктора. За основу берутся действующие функции и поведение сайта KRAZBURG.

| Область | Актуальное решение |
| --- | --- |
| Интерфейс | Nuxt, новый дизайн по макетам, компьютер и телефон |
| CMS | Strapi: страницы, тексты, изображения, FAQ, отзывы, контакты, навигация и подсказки конструктора |
| Виды потолков и опции | Добавление, изменение, скрытие, публикация и предусмотренные параметры в CMS, в рамках существующей расчётной модели |
| Расчёт | Перенос существующих формул, геометрии, ограничений, округлений и поведения выбора. На одинаковых данных результат совпадает |
| Оформление | Сохранённый расчёт по ссылке, Ozon Pay, проверка статусов и действующая доставка/обработка заказов сохраняются |
| Новые возможности | Универсальный редактор формул, точная геометрия вместо эскиза, новые платёжные сценарии, отдельный движок торговли и готовые конфигурации сверх существующей модели не добавляются автоматически |
| Эксплуатация | Timeweb Monitoring с автоматическими уведомлениями; одно ночное копирование в сутки в S3 |

Отдельная контактная заявка менеджеру и email-уведомления не заменяют действующий заказ. Прежние выводы об исключении Ozon из первой очереди устарели. Формулировки в отчётах до этого уточнения фиксируют историю обсуждения.

Клиентские части исследованы по кэшу 2 ноября и работающему сайту 5 ноября. Серверное создание расчётов, интеграция оплаты и админка не проверены сквозным оформлением реальных заказов. Для точного переноса требуются исходники сервера, данные и настройки подключения Ozon Pay. Подробности описаны в разделе 9 публичного ТЗ.

Добавление CMS не считается автоматическим исправлением особенностей прототипа. Любое изменение алгоритма или сценария относительно действующего поведения фиксируется отдельным согласованным изменением. Сохранённые расчёты и оплаченные заказы сохраняют состав и зафиксированные данные при изменении каталога.

Нормализатор `te` исключает группы с `hidden: true` до передачи данных интерфейсу. В результате активная конфигурация содержит шесть основных групп с 97 позициями и 26 дополнительных позиций карниза. Карниз выбирается по схеме `select: one`; остальные видимые группы — `select: many`.

Данные позиции включают `id`, `label`, `hint`, `rate`, `image`, необязательные `unit`, `packOf`, `stickLengthsM`, `sizeTiers`. В группах задаются `basis` (периметр, длина либо количество), `roundUpTo`, `pieceMaxM`, дополнения и режим выбора. Отдельных полей SKU, складского остатка и доступности товара в этом ответе нет. Отсутствие таких полей не доказывает, что на сервере вообще нет складского учёта.

В JSON нет отдельного массива готовых конфигураций или общей матрицы совместимости всех комплектующих. Группа «Базовый комплект» — перечень отдельных товаров. Установить существование отдельного каталога заранее собранных комплектов только по этому ответу нельзя.

## Совместимость полотен и качество данных

Допустимые сочетания полотна задаются таблицей `canvases`. Белые hot/soft поддерживают матовый, сатин, глянец и Bauf; cold — только белый матовый; цветные hot/soft — матовый, сатин и глянец. Полупрозрачный материал есть в справочнике, но для него нет строки `canvases`, поэтому он не попадает в допустимый выбор через функцию `ce`.

В восьми идентификаторах товаров есть пробелы по краям, у 33 позиций нет явной единицы. Это особенности исходного JSON, не доказанные ошибки интерфейса: помощник `T` обрезает пробелы, а `me` подставляет единицу по типу группы. Нормализатор также отсеивает невалидные записи и ограничивает числовые параметры. При переносе данных следует сохранять смысл идентификаторов и единиц, а не копировать сырой JSON без нормализации.

В конфигурации 111 различных URL изображений групп и товаров. Ни один из этих точных URL не совпадает с единственным сохранённым ответом `/api/media.php`. Большая часть фотографий товаров для полноценного визуального воспроизведения отсутствует; на изучение формул это не влияет.

## Резервный прайс и загрузка данных

В `CeilingCalc` встроен отдельный резервный прайс версии 8 от 15 октября 2026 года. Он отличается от публичного прайса версии 150: например, минимальная сумма 550 ₽ вместо 2500 ₽, посылка 400 ₽ вместо 300 ₽, минимальная сторона 5 см вместо 3 см.

Функция `kd` выбирает загруженный прайс либо встроенный `P`. При обычной сетевой ошибке запрос возвращает состояние без прайса и используется резервный набор. Специальный ответ 503 с кодом `maintenance` обрабатывается отдельно. Для достоверного воспроизведения архива нужно подставить сохранённый ответ `/api/public.php`, включая запросы с параметром `v`; иначе исследователь увидит другую стоимость и другой ассортимент.

Источники в производном `research/cache-2026-11-02/CeilingCalc.formatted.js`: `T` — строка 42; `N`/`te`/`ne` — строки 77–108; единицы `me` — строка 114; выбор полотен `ce` — строка 112; загрузка и fallback — строки 3663–3697. Это удобная форматированная копия сохранённого бандла, а не авторский исходный проект.

## Чего не хватает для полного восстановления

| Область | Что известно | Что не подтверждается архивом |
| --- | --- | --- |
| Сохранение расчёта | Клиент вызывает POST `/api/calc.php` | Серверная проверка, хранение, ответ успешного запроса |
| Повторное открытие расчёта | Клиент вызывает GET `/api/calc.php?id=…` | Срок действия, права доступа, реальное восстановление сохранённого расчёта |
| Оплата | Есть вызов POST `/api/pay.php` | Платёжный сервис, чек, статусы и фактический успешный платёж |
| Статус расчёта | Есть GET `/api/calc-status.php?id=…` | Серверный жизненный цикл, реальные ответы и переходы |
| Аналитика | Есть POST `/api/track.php` | Приём и использование событий сервером |
| Администрирование | Публичный прайс содержит настройки и товары | Интерфейс админки, роли, редактор правил, способ сохранения изменений |
| Остальные страницы | Навигация ссылается на `/otzyvy` и материалы монтажа | Полные тела этих страниц и все связанные ресурсы |

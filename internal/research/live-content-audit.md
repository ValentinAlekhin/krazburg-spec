В FAQ упоминаются точные диагонали сложного помещения, кнопка «Оплатить», доставка Ozon и дальнейшее согласование параметров. Эти маркетинговые пояснения нужно сопоставлять с реальным интерфейсом и серверным сценарием; они сами по себе не доказывают точность геометрии или успешность оплаты. Согласованный первый этап нового проекта заканчивается заявкой менеджеру.

## Страница отзывов

Страница `/otzyvy` содержит вводный блок, заявленную оценку и число отзывов, ссылку на источник Ozon, кнопку расчёта и десять карточек отзывов с медиагалереями. В HTML присутствуют пять видеоэлементов. Тела видео в рамках этой проверки не скачивались, воспроизведение не проверялось.

Отзывы уже включены в HTML. Полученный модуль `ReviewCard` совпадает с ранее сохранённым. Подтверждений автоматической синхронизации отзывов с API Ozon, пользовательской формы отправки отзывов, модерации или сортировки в выполненной проверке нет. Наличие ссылки на Ozon не означает интеграцию импорта. Имена покупателей и тексты отдельных отзывов в отчёт не перенесены.

## Каталог и конфигурация

Текущий ответ API повторяет разобранную [структуру данных кэша](./data-audit.md): 13 групп, 132 основные позиции и 26 дополнений карниза, всего 158 уникальных позиций. После фильтрации скрытых групп остаются шесть основных групп и 123 позиции вместе с дополнениями. Прайс содержит параметры упаковки, единицы, тарифы и сочетания полотен; отдельных складских остатков, SKU и доступности товаров в этом ответе нет.

Обозначение «Базовый комплект» остаётся группой отдельных товаров. Отдельный каталог заранее настроенных готовых проектов по текущим публичным страницам и API не подтверждён. Появления новых материалов, групп, цен или ограничений по сравнению с кэшем не обнаружено: ответ совпадает полностью.

Три проверенных изображения групп весят от 2,04 до 2,47 МБ. Это отдельное наблюдение о ресурсах прототипа: при проектировании нового сайта нужны подготовленные превью и подходящие размеры изображений, чтобы открытие каталога не требовало загрузки полноразмерных исходников. Размеры всех изображений каталога не измерялись.

В исходном HTML `/raschet` есть резервное значение минимальной суммы 550 ₽, а текущий API задаёт 2500 ₽. Это соответствует уже найденным прайсам v8 и v150. Из чтения HTML нельзя заключать, что после загрузки JavaScript покупатель продолжает видеть 550 ₽; окончательное состояние проверяется в браузере.

## Следы управления контентом

HTML содержит атрибуты `data-cms`, `data-cms-list`, `data-cms-img`, `data-cms-video`, подписи и ограничения полей. На главной обнаружено 159 текстовых маркеров, на странице конструктора — 36, на странице отзывов — 62. Среди помеченных объектов — меню, заголовки, тексты кнопок, преимущества, способы монтажа, FAQ, отзывы, фото, видео, пояснения расчёта и подвал.

Это свидетельство предусмотренной разметки для управления контентом. Текущая административная панель и возможность фактического редактирования через неё не проверялись. Для нового проекта источник управления остаётся согласованным Strapi.

## Что требуется учесть при дальнейшем заполнении ТЗ

Эти наблюдения полезны для конкретизации функциональности; новые возможности необходимо отличать от уже согласованных требований:

- Описать главную страницу, FAQ, помощь с замерами, информацию о способах монтажа и связь с менеджером, а не только экраны расчёта.
- Определить поведение и управление отзывами, изображениями и видео в Strapi, если эти блоки сохраняются в новом сайте. Автоматический импорт Ozon не считать существующим подтверждённым требованием.
- Предусмотреть отдельное согласование с менеджером для нестандартных решений, например фотопечати; не превращать каждое такое решение в автоматическую опцию калькулятора.
- Зафиксировать место текстов о доставке и материалах. Автоматическая доставка и оплата не входят в согласованный первый этап.
- Подтвердить у владельца необходимые юридические тексты и ссылки: в найденной навигации полноценных документов нет. Этот аудит не оценивает юридическую достаточность текущего сайта.
- Сопоставить обещания FAQ о точном чертеже и оформлении с проверенной логикой, чтобы новый интерфейс не обещал возможностей сверх реализованных и согласованных.

Из этой проверки нельзя получить данные об админке, серверной валидации и хранении, настоящих платёжных ответах и внутренней организации производства. Публичные страницы и клиентские данные стали доступны; для перечисленных серверных вопросов по-прежнему нужны исходники либо безопасный доступ к соответствующей части работающего проекта.

## Проверка галереи, FAQ и мобильной навигации в браузере

Дополнительно страницы открыты в чистом Chromium. JavaScript, CSS и HTML получены с работающего сайта. Для ограничения загрузки фото заменялись маленьким техническим изображением; запросы видео, внешние адреса и любые методы кроме GET блокировались. Полные фотографии и видео не скачивались, ссылки Ozon и кнопки связи не нажимались. Такая проверка подтверждает работу элементов управления, но не качество медиа и воспроизведение видео.

| Действие | Проверенный результат |
| --- | --- |

| Нажать «Следующее» и «Предыдущее» | Счётчик меняется `1 / 3 → 2 / 3 → 1 / 3` |

JavaScript-ошибок в выполненных сценариях не зарегистрировано. Исследована одна галерея с тремя элементами; проход всех фотографий и всех десяти отзывов не заявляется. Воспроизводимый сценарий и результаты без имён покупателей находятся в `research/live-2026-11-05/content-browser-check.mjs` и `content-browser-check.json`. Эти файлы остаются вне Git.

# Техническое задание KRAZBURG

Окружение для подготовки ТЗ: VitePress, диаграммы Mermaid и инструменты исследования текущего сайта. Задача проекта — CMS Strapi и новый дизайн на Nuxt с сохранением действующих конструктора, заказов и Ozon Pay. Актуальные границы работ записаны в [internal/project-scope.md](internal/project-scope.md).

## Работа с документацией

Нужны Node.js 22.12 или новее и npm; в GitHub Actions используется Node.js 24.

```bash
npm ci
npm run docs:dev
```

Страницы для заказчика находятся в [docs/](docs/index.md). Внутренние материалы хранятся отдельно: [инструкции по заполнению](internal/guide/authoring.md), [выбор пакетов](internal/guide/tooling.md), [исследование референсов](internal/research/references.md) и [аудит прототипа](internal/research/current-site.md). Папка `internal/` не входит в сборку GitHub Pages, навигацию и поиск заказчика.

Сборка и проверка готового сайта:

```bash
npm run docs:build
npm run docs:check
npm run docs:preview
```

Для браузерной проверки нужен установленный Chrome/Chromium либо `npx playwright install chromium`. При необходимости задайте `CHROME_PATH`.

GitHub Pages настраивается через [.github/workflows/docs.yml](.github/workflows/docs.yml). В целевом репозитории выберите **Settings → Pages → Source → GitHub Actions**. Публикация выполняется после успешных проверок при обновлении `main`; в pull request выполняются только проверки. Путь сайта берётся из настроек Pages, включая адрес вида `owner.github.io/repository/`. Локальная проверка такого адреса:

```bash
VITEPRESS_BASE=/press/ npm run docs:build
VITEPRESS_BASE=/press/ npm run docs:check
VITEPRESS_BASE=/press/ npm run docs:preview
```

Репозиторий: [ValentinAlekhin/krazburg-spec](https://github.com/ValentinAlekhin/krazburg-spec). Адрес сайта ТЗ: [valentinalekhin.github.io/krazburg-spec/](https://valentinalekhin.github.io/krazburg-spec/).

## Снимок сайта для аудита

[Загрузчик](scripts/download-site.mjs) открывает сайт в браузере и сохраняет файлы, которые загружаются при вашем прохождении конструктора: HTML, JavaScript, стили, изображения, шрифты и публичные JSON-ответы GET-запросов. Он также делает снимки выбранных шагов: скриншот и текущее содержимое страницы.

Это материал для изучения интерфейса и логики расчёта. Серверный код таким способом получить нельзя; сохранённый сайт не обязательно будет работать без интернета.

## Установка

Нужны Node.js 22.12 или новее и npm. В папке проекта выполните:

```bash
npm install
```

В Linux скрипт автоматически ищет установленный Google Chrome или Chromium. Если подходящего браузера нет, установите Chromium для Playwright:

```bash
npx playwright install chromium
```

При необходимости укажите путь к браузеру через `--browser-path`, как в примере ниже.

## Загрузка сайта

Отключите VPN самостоятельно, если сайт доступен только без него, и запустите:

```bash
npm run download:site -- --url https://krazburg.ru --out ./research/krazburg
```

Откроется отдельное окно браузера. Пройдите конструктор вручную; скрипт будет сохранять загружаемые ресурсы, включая файлы, которые появляются только при выборе опций или переходе между шагами. Страницы сами по себе он не обходит и кнопки не нажимает.

Команды вводятся в терминале, где запущен скрипт:

| Команда | Действие |
| --- | --- |
| Enter | Сохранить снимок текущего шага |
| `save размеры` | Сохранить снимок с названием «размеры» |
| `save итог` | Сохранить итоговый расчёт |
| `q` или `quit` | Сохранить финальное состояние и завершить загрузку |
| Ctrl+C | Завершить с сохранением доступных материалов |

Для аудита откройте готовые комплекты и расчёт с нуля, меняйте параметры по одному, проверяйте необязательные поля, допустимые минимальные и максимальные размеры, переходы назад и обновление страницы. Сохраняйте снимки перед изменением параметра и после него. Реальные контактные данные и отправка заявки для этого не нужны.

Дождитесь сообщения о завершении записи перед тем, как переносить результат. Если папка результата уже содержит файлы, выберите новую: существующий снимок не перезаписывается. Без `--out` создаётся папка `research/<имя-сайта>-<время>`.

## Дополнительные параметры

Системный браузер по явному пути:

```bash
npm run download:site -- --url https://krazburg.ru --browser-path /path/to/google-chrome
```

Увеличенный тайм-аут открытия страницы, в миллисекундах:

```bash
npm run download:site -- --url https://krazburg.ru --timeout 60000
```

Быстрый автоматический снимок без окна браузера:

```bash
npm run download:site -- --url https://krazburg.ru --headless --duration 10
```

В режиме `--headless` браузер закрывается после указанного числа секунд; по умолчанию — через 5 секунд. Этот режим сохраняет начальную страницу и её ресурсы. Для изучения всех шагов конструктора используйте обычный режим с окном.

## Что передать для аудита

Передайте целиком папку результата, при необходимости упаковав её в архив:

| Файл или папка | Содержимое |
| --- | --- |
| `assets/` | Загруженные файлы с именами на основе URL |
| `manifest.json` | Соответствие адресов ресурсов сохранённым файлам и статусы ответов |
| `states/` | Скриншоты и HTML сохранённых шагов |
| `errors.jsonl` | Ошибки браузера и загрузки ресурсов |
| `summary.json` | Итог загрузки и сведения о неполном снимке |

При ошибке DNS или недоступности страницы скрипт завершится с ошибкой и сохранит диагностику. Отдельные не загрузившиеся ресурсы будут отмечены в отчёте; их наличие не означает, что остальная копия бесполезна. Заголовки запросов и cookies не сохраняются. Содержимое открытых страниц и публичные ответы сервера входят в снимок, поэтому используйте отдельное окно скрипта без входа в личные кабинеты.

Ответы больше 25 МиБ и запросы, не завершившиеся к концу сеанса, отмечаются как пропущенные. Коды завершения: `0` — загрузка завершена без зафиксированных ошибок, `2` — частичный снимок или прерывание, `1` — ошибка запуска либо открытия сайта. Это не проверка полноты обхода: сохраняются только посещённые состояния и реально загруженные ресурсы.

Папка `research/` исключена из Git. Загрузчик не меняет настройки VPN или сети.
